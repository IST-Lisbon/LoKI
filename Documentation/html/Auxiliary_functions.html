5.1 Property functions

Property functions are *.m functions that can be used to specify the properties of gases and states used in the simulations. Some property functions are distributed with LoKI, but in general these functions can be prepared by the user, according to the needs for new functionalities. In this case, the user is advised to mimic the structure of any property function already provided with the code.

The following should be considered:

  • for organisation sake, all "property functions" specified in the setup file should be located in the property functions folder ([repository folder]/LoKI-GM_26.07/Code/PropertyFunctions; see section 2.2);
  • property functions have the arguments (state, argumentArray, workCond), or (gas, argumentArray, workCond), where
    • state or gas: is a handle to the state/gas-object(s) to which the property is assigned.
      For example, when using N2(X,v=*) the property is assigned to all the vibrational states with the electronic ground-state of N₂;
    • argumentArray: is an array of arguments corresponding to the list of parameters to be used in the setup file (see below);
    • workCond: is a handle to the working-conditions-object of the simulation.
  • property functions are called from the setup file (see section 3) using the following structure:

    <function name> @[list of parameters] ⏟ Optional
    where the list of parameters is a list of comma-separated values with all the parameters called by the particular property function. The parameters sent to the property functions can be mapped to the values of the different working conditions previously defined in the setup file (see Code 3.2 and Code 3.3 for examples, and therein the implementation of property function boltzmannPopulation@gasTemperature) and generalizedTemperatureDependentCoeff@5.0e20/sqrt(300),gasTemperature,0.5);
  • property functions MUST be set only for those gases and states used in the simulations, i.e. those listed in the specified LXCat files.

The property functions in table 3 correspond to the following physical models:

harmonicOscillatorEnergy
It calculates the energy of (vibrational) state j of a diatomic molecule, adopting the harmonic oscillator model E j = ℏ ω vib e ( j + 1 2 ) , where ωvib is the harmonicFrequency (angular frequency) of the molecule.
morseOscillatorEnergy
It calculates the energy of (vibrational) state j of a diatomic molecule, adopting the Morse oscillator model E j = ℏ ω v i b e ( j + 1 2 ) − ℏ ω vib χ e e ( j + 1 2 ) 2 , where ωvibχe is the first anharmonicFrequency of the molecule (with χe the anharmonicity constant).
rigidRotorEnergy
It calculates the energy of (rotational) state J of a diatomic molecule, adopting the rigid-rotor model E J = B J ( J + 1 ) , where B is the rotational constant of the molecule.
rigidRotorEnergy_NH3
it calculates the energy of (rotational) states (J, K) with K = 0 of NH3, following the work of Dowling [27], which shows good agreement with the MARVEL database [28, 29] EJ=BJ(J+1)−8.407×10−2t(J(J+1))2+2.38×10−5t(J(J+1))3,witht=hc/e.

These property functions should be called within the energy property of the setup file, for the corresponding vibrational and rotational states.

For example: 

  N2(X,v=*) = harmonicOscillatorEnergy
to set the energies of all the vibrational states with the electronic ground-state of N₂.

  N2(X,v=0,J=*) = rigidRotorEnergy
to set the energies of all the rotational states of the vibrational state v=0, with the electronic ground-state of N₂.

rotationalDegeneracy
It calculates the statistical weight of the intrinsic partition function of a (generic) rotational state J [19] gJ=2J+1.
rotationalDegeneracy_N2
It calculates the statistical weight of the intrinsic partition function of a rotational state J of the N₂ molecule [19] gJ=3 [1+12(1+(−1)J)](2J+1).
rotationalDegeneracy_H2
It calculates the statistical weight of the intrinsic partition function of a rotational state J of the H₂ molecule [19] gJ=[2−(−1)J](2J+1).
rotationalDegeneracy_NH3
It calculates the statistical weight of the intrinsic partition function of a rotational state (J,K), with K=0 of the vibrational ground-state (v1=0, v2=0, v3=0, v4=0) of NH3, considering that the state (0,0) has a double degeneracy [28] gJ=2(2J+1)for J=0gJ=2J+1for J=1,2,3,….

These property functions should be called within the statisticalWeight property of the setup file, for the corresponding vibrational and rotational states (see also section 3.2).

For example: 

    N2(X,v=0,J=*) = rotationalDegeneracy_N2
to set the statistical weights of all the rotational states of the vibrational state v=0, with the electronic ground-state of N₂.

boltzmannPopulation
It calculates the population of state j, adopting the Boltzmann distribution ξ j = g j exp ⁡ − E j k B T ∑ i ∈ siblings g i exp ⁡ − E i k B T , where T is the characteristic temperature of the distribution.

boltzmannRotationalPopulation_H2
It calculates the population of rotational state j of H2 , adopting Boltzmann distributions for the ortho/para configurations, with weights 25% and 75%, respectively ξjeven=0.25gjevenexp⁡−EjevenkBT∑i∈siblingsgievenexp⁡−EievenkBTξjodd=0.75gjoddexp⁡−EjoddkBT∑i∈siblingsgioddexp⁡−EioddkBT, where T is the characteristic temperature of the distribution.
boltzmannPopulationRotationalCutoff
It calculates the population of rotational state J, adopting a Boltzmann distribution truncated at level JMAX ξ J = g J exp ⁡ − E J k B T ∑ J ′ = 0 J MAX g J ′ exp ⁡ − E J ′ k B T , where T is the characteristic temperature of the distribution.
This distribution allows defining the populations of rotational states to be considered in the solution to the electron Boltzmann calculation, irrespectively of the full list of states involved in electron collision events (for example, appearing also in extra cross section files).

boltzmannPopulationVibrationallCutoff
It calculates the population of vibrational state v, adopting a Boltzmann distribution truncated at level vMAX ξ v = g v exp ⁡ − E v k B T ∑ v ′ = 0 v MAX g v ′ exp ⁡ − E v ′ k B T , where T is the characteristic temperature of the distribution.
This distribution allows defining the populations of vibrational states to be considered in the solution to the electron Boltzmann calculation, irrespectively of the full list of states involved in electron collision events (for example, appearing also in extra cross section files).

treanorPopulation
It calculates the population of state j, adopting the Treanor distribution [30,31] ξ j = g j exp ⁡ j ( E 1 − E 0 ) − ( E j − E 0 ) k B T 0 exp ⁡ − j ( E 1 − E 0 ) k B T 1 ∑ i ∈ siblings g i exp ⁡ i ( E 1 − E 0 ) − ( E i − E 0 ) k B T 0 exp ⁡ − i ( E 1 − E 0 ) k B T 1 , where T₀ and T₁ are the characteristic temperatures of the distribution.

treanorGordietsPopulation
It calculates the population of state j, adopting the Treanor-Gordiets distribution [18,19] ξ j = { g j exp ⁡ j ( E 1 − E 0 ) − ( E j − E 0 ) k B T 0 exp ⁡ − j ( E 1 − E 0 ) k B T 1 ∑ i ∈ siblings ξ i , j ≤ j ⋆ ξ j ⋆ j ⋆ j ∑ i ∈ siblings ξ i , j > j ⋆ , where T₀ and T₁ are the characteristic temperatures of the distribution and j⋆≡12[1+E1−E0ℏωvibχeT0T1] is the vibrational level corresponding to the minimum of the Treanor distribution (with ωvibχe the anharmonic frequency of the oscillator characterizing the distribution).

These property functions should be called within the population property of the setup file, for the corresponding states, using
boltzmannPopulation@〈temperature〉
boltzmannPopulationRotationalCutoff@〈temperature〉,〈JMAX〉
treanorPopulation@〈temperature0〉,〈temperature1〉
where temperature, temperature0, temperature1 can be temperature values for the dynamic variables gasTemperature or electronTemperature.
For example: 

N2(X,v=*) = treanorPopulation@gasTemperature,4000
to set the population of all the vibrational states with the electronic ground-state of N2; 
N2(X,v=0,J=*) = boltzmannPopulation@gasTemperature
to set the population of all the rotational states of the vibrational state v=0, with the electronic ground-state of N2.

generalizedTemperatureDependentCoeff
It calculates a general property (e.g., reducedMobility or reducedDiffCoeff) aTb, where the normalization constant a, the temperature T and the power b should be specified as parameters to the function.
mobilityHeliumAtomicIon
It calculates the reducedMobility of the helium atomic ion [32] abT0.5+c, where the normalization constant a, the temperature T and the quantities b, c should be specified as parameters to the function.
diffusionHeliumAtomicIon
It calculates the reducedDiffCoeff of the helium atomic ion [32] abT0.5+ckBTe, where the normalization constant a, the temperature T and the quantities b, c should be specified as parameters to the function.
tableEoNDependentMobility
It interpolates the reducedMobility for the current value of the reduced electric field, from a table with filename specified as parameter to the function.
temperatureDependentEinsteinDiffCoeff
It calculates the reducedDiffCoeff from the Einstein relation μeNkBTe, where the temperature T should be specified as parameter to the function, and the reduced mobility μeN is obtained from the workingConditions.

These property functions should be called within the reducedMobility and reducedDiffCoeff properties of the setup file, for the corresponding states, using for example

reducedMobility:
He(2S3) = generalizedTemperatureDependentCoeff@8.6155e+19,gasTemperature,0.5
He(+,1S2) = mobilityHeliumAtomicIon@2.68e21,2.96e-3,3.11e-2,gasTemperature
O(+,gnd) = tableEoNDependentMobility@Databases/IonMobilities/O+_O2.txt
reducedDiffCoeff:
He(+,1S2) = diffusionHeliumAtomicIon@2.68e21,2.96e-3,3.11e-2,gasTemperature
O2(+,X) = temperatureDependentEinsteinDiffCoeff@gasTemperature

nitrogenHeatCapacity
It calculates the nitrogen heat capacity [33] Cp(N2)=29.1+2494.2553.4π/2exp⁡(−2(Tg−1047.4553.4)2).
oxygenHeatCapacity and oxygenAtomHeatCapacity and ozoneHeatCapacity
It calculates the heat capacity of O, O2 and O3 [34] Cp(O,O2,O3)=8.314510(a1Tg−2+a2Tg−1+a3+a4Tg+a5Tg2+a6Tg3+a7Tg4), where a1, ..., a7 are NASA polynomial coefficients taken from [34]: p. 164 for atomic oxygen; p. 166 for molecular oxygen and ozone.

These property functions should be called within the heatCapacity property of the setup file, for the corresponding states, using for example

heatCapacity:
O2 = oxygenHeatCapacity

nitrogenThermalConductivity
It calculates the nitrogen thermal conductivity [33] λg(N2)=(1.717+0.084Tg−1.948×10−5Tg2)×10−3,
oxygenThermalConductivity and oxygenAtomThermalConductivity
It calculates the thermal conductivity of O2 and O [35] λg(O,O2)=10−4exp⁡(a1ln⁡Tg+a2Tg+a3Tg2+a4), where a1 , ..., a4 are transport coefficients taken from [35] p. 86.

These property functions should be called within the thermalConductivity property of the setup file, for the corresponding states, using for example

thermalConductivity:
O2 = oxygenThermalConductivity

5.2 Rate coefficient functions

Rate coefficient functions are '*.m' functions that compute the rate coefficients of the reactions included in the kinetc mechanisms. Some of these functions are distributed with LoKI, implementing the most common types of rate coefficients and useful models. In general these functions can be prepared by the user, according to the needs for new functionalities. In this case, the user is advised to mimic the structure of any rate coefficient function already provided with the code.

The following should be considered:

  • For organisation sake, all "rate coefficient functions" specified in the different auxiliary input files should be located in the rate coefficient functions folder [repository folder]/LoKI-GM_20.07/Code/RateCoeffFunctions, which is organized into one-level subfolders with self-explanatory names (see section 2.2), for example:
    • ElectronKinetics
    • General
    • specific folders with functions for gases (Nitrogen, Oxygen, ...)
    • SurfaceKinetics
    • TransportIons
    • TransportNeutrals.
  • rate coefficient functions have the arguments (time, densitiesAll, totalGasDensity, reaction, rateCoeffParams, chemistry) where
    • time: is the current time at which the function is called;
    • densitiesAll: is an array with the density values of all the states involved in the simulations;
    • totalGasDensity: is the the current value of the total gas density;
    • reaction: is a handle to the reaction-object of the simulation;
    • rateCoeffParams: is an array of arguments corresponding to the list of parameters to be used in the calculation of the rate coefficient (see tables 4 and 5-9);
    • chemistry: is a handle to the chemistry-object of the simulation.
  • rate coefficient functions are called from the auxiliary chemistry files (see section 4.3) using the following structure:

    ... | <𝚛𝚊𝚝𝚎 𝚌𝚘𝚎𝚏𝚏𝚒𝚌𝚒𝚎𝚗𝚝>𝚓⏟Type of rate coefficient | <𝚙𝚊𝚛𝚊𝚖𝚎𝚝𝚎𝚛𝚜>⏟Parameters needed | ... where
    • <rate coefficient> is the field with the name of the function that computes the rate coefficient;
    • <parameters> is a list of comma separated values with all the parameters (if any) required for the corresponding rate coefficient function.
  • rate coefficient functions MUST conclude with a list of dependencies true/false
    • onTime
    • onDensities
    • onGastemperature
    • onElectronKinetics

    for example: 

        dependent = struct('onTime', false, 'onDensities', false, 'onGasTemperature', false, 'onElectronKinetics', true)

The functions supplied with the code can be divided into two categories: those corresponding to simple expressions (see table 4) and those corresponding to more elaborated implementations based on specific models (see tables 5-9).

5.3 Other auxiliary functions

In OtherAuxFunctions the user can find *.m functions

  • for evaluating the time derivative of the EEDF at a given time t. In the current distribution of LoKI, this function is eedfTimeDerivative.m and is not optimized for standalone LoKI-B calculations;
  • for calculating working conditions that can evolve during the simulations. In the current distribution of LoKI, this functionality is for calculating the reducedField in the case of LoKI-B calculations for step electric fields (function reducedFieldRamp.m) or electric field pulses (function reducedFieldPulse.m);
  • for obtaining the reduced electric field resulting from the imposition of a time-dependent discharge current (functions reducedFieldFromCurrentFile.m and getEoNFromCurrent.m)
In general these functions can be prepared by the user, according to the needs for new functionalities. In this case, the user is advised to mimic the structure of any auxiliary function already provided with the code.

5.4 Utilities

In folder Utilities the user can find scripts

  • for plotting two different EEDFs in the same MATLAB® graph. In the current distribution of LoKI, this function is compareEEDFs.m;
  • for plotting the errors associated with the convergence cycles from the log-file. In the current distribution of LoKI, this function is graphical_log.m;
  • for interactively assist the modification of LXCat text-files, for compliance with the LoKI-B parser. In the current distribution of LoKI, this function is LXCat2LoKI.m.
